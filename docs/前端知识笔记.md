# 前端知识笔记：从 index.html 到 ApiServer

> 配套项目：StudentManager（原生 JS + JDK HttpServer）
> 用法：每节先看「一句话」，再对照自己项目里的代码，最后做自测清单。
> 标记：★★★ 必须会背 / ★★ 要能看懂 / ★ 知道有这回事就行

---

## 0. 先记住这一条链路

你在浏览器点「提交」，到数据库里多一条记录，中间只发生了一件事：**一段文本被送到了服务器，服务器回了一段文本。**

```
[浏览器]                                            [服务器 JVM]
index.html  ──┐
style.css   ──┼─→ StaticHandler ─→ classpath:/static/*
app.js      ──┘

app.js 里 fetch('/api/students', {method:'POST', body:'{"name":"张三",...}'})
        │
        │  ① 拼 HTTP 请求（方法 + 路径 + 头 + 体）
        ▼
   ┌─ HTTP 报文（纯文本）─────────────────────┐
   │ POST /api/students HTTP/1.1              │
   │ Content-Type: application/json           │
   │                                          │
   │ {"name":"张三","gender":"男","age":20}    │
   └──────────────────────────────────────────┘
        │
        ▼
ApiServer 按路径分发 ─→ StudentHandler.handle()
        │                    │
        │                    ├─ readBody()  把字节读成 String
        │                    ├─ Json.MAPPER.readValue(body, Student.class)  ← JSON 字符串 → Java 对象
        │                    ├─ studentService.addStudent(stu)  ← 复用你原来的 Service，一路到 DAO、MySQL
        │                    └─ Json.sendObject(exchange, 201, stu)  ← Java 对象 → JSON 字符串
        ▼
   响应报文： HTTP/1.1 201 + {"id":7,"name":"张三",...}
        │
        ▼
app.js: const res = await fetch(...)   ← Response 对象（头 + 状态码 + body 流）
        const data = await res.json()  ← JSON 字符串 → JS 对象
        renderRows(list)               ← JS 对象 → DOM 节点 → 屏幕上出现新行
```

**四个转换点，整份笔记就是围绕它们展开的：**

| # | 位置 | 从 | 到 | 靠什么 |
|---|------|----|----|--------|
| 1 | 前端发请求前 | JS 对象 | JSON 字符串 | `JSON.stringify()` |
| 2 | 后端收请求后 | JSON 字符串 | Java 对象 | `Json.MAPPER.readValue()` |
| 3 | 后端返回前 | Java 对象 | JSON 字符串 | `Json.MAPPER.writeValueAsString()` |
| 4 | 前端收响应后 | JSON 字符串 | JS 对象 | `await res.json()` |

中间的载体永远是 HTTP 报文，说白了就是一堆字符。**你以前在命令行用 `curl` 干的事，浏览器每天都在干。**

## 1. 三个文件怎么咬合 ★★★

### 1.1 各管一段，互不越界

| 文件 | 管什么 | 不管什么 |
|------|--------|----------|
| `index.html` | 结构：有哪些元素、id 叫什么、谁套着谁 | 长什么样、点了会怎样 |
| `style.css` | 外观：颜色、间距、布局 | 有任何逻辑 |
| `app.js` | 行为：数据从哪来、点了做什么、页面怎么变 | 决定元素长什么样 |

三者的唯一连接方式是 **HTML 里的 id / class / name 这几个"名字"**。
`app.js` 靠 id 找到元素，`style.css` 靠 class 找到元素。名字一改，另一头立刻断。

### 1.2 为什么 HTML 只写了个 `href="style.css"` 就能拿到文件

页面地址是 `http://localhost:8080/`，`href="style.css"` 是**相对路径**，浏览器拼成 `http://localhost:8080/style.css`，发第二个请求。

服务器那边：

```
GET /style.css
  → ApiServer 的 createContext("/", StaticHandler) 兜底匹配
  → path = "/style.css"
  → getResourceAsStream("/static" + "/style.css")
  → classpath:/static/style.css  ← 就是 src/main/resources/static/style.css
  → 按扩展名设 Content-Type: text/css
```

所以：**`static/` 这个目录名在 URL 里是看不见的**，它只在 Java 代码里出现一次（`"/static" + path`）。你在 HTML 里写 `href="/static/style.css"` 反而会 404。

同理 `app.js` 也是浏览器单独发的一个请求，扩展名 `.js` → `Content-Type: application/javascript`，浏览器才肯当脚本执行。

### 1.3 `<script>` 放 body 最后，不是随便放的 ★★★

```html
<body>
  ...所有元素...
  <script src="app.js"></script>
</body>
```

浏览器从上往下解析 HTML：遇到 `<script>` 会**停下来**，先下载并执行完这个 js，再继续解析下面的 HTML。

`app.js` 第一行就是：

```js
const classSelect = document.getElementById('classid');
```

如果这个 `<script>` 放在 `<head>` 里，执行到这一行时 `<select id="classid">` 还没被解析出来，`getElementById` 返回 `null`，下一句 `classSelect.value` 直接报错：

```
Uncaught TypeError: Cannot read properties of null (reading 'value')
```

三种解法（任选其一）：

| 写法 | 说明 |
|------|------|
| 放 body 末尾（你现在这样） | 最简单，DOM 已就绪 |
| `<script defer src="app.js">` 放 head | 下载不阻塞解析，DOM 解析完后按顺序执行 |
| 用 `DOMContentLoaded` 包起来 | `document.addEventListener('DOMContentLoaded', () => {...})` |

**注意区别：`<script src>` 只是"引入文件"，不是"调用函数"。** 文件一被引入，里面顶层写的代码（抓节点、`addEventListener`、最后那行 `loadClasses()`）就立刻执行。`function loadStudents(){}` 只是定义，没人调用就不会跑。

## 2. 抓住节点：DOM 查询 ★★★

### 2.1 什么是 DOM

浏览器把 HTML 文本解析成一棵树，每个标签变成一个 **节点对象**（Element），挂在 `document` 下面。

```html
<tbody id="studentRows"></tbody>
```
变成
```js
document
 └ body
    └ main.page
       └ section.table-wrap
          └ table
             └ tbody#studentRows   ← 一个对象，有属性有方法
```

**关键认知：拿到节点 = 拿到一个 JS 对象。** 这个对象上有 `textContent`、`value`、`classList`、`appendChild` 这些属性/方法，你调它，页面就变。不存在"直接改 HTML 文件"这回事，改的都是内存里的这棵树。

### 2.2 三个查询方法

| 方法 | 返回 | 找不到时 | 用在 |
|------|------|----------|------|
| `getElementById('x')` | 单个 Element | `null` | HTML 里有 `id="x"` |
| `querySelector('.x')` / `('tr > td')` | 第一个匹配 | `null` | 想用 CSS 选择器 |
| `querySelectorAll('.x')` | NodeList（类数组，可 `for...of`） | 空 NodeList | 批量 |

你项目里全是第一种，因为 HTML 里都写好了 id：

```js
const classSelect = document.getElementById('classid');   // <select id="classid">
const tbody       = document.getElementById('studentRows'); // <tbody id="studentRows">
const addForm     = document.getElementById('addForm');     // <form id="addForm">
```

还有两个不走 `document` 的入口，很实用：

```js
addForm.elements['name']      // 表单内按 name 取控件，等价于 document.querySelector('input[name="name"]')
tr.querySelector('.delete')   // 在某个节点内部找，只在这个子树里搜
```

### 2.3 抓不到就是 null，这是新手第一大报错

```js
const el = document.getElementById('studentRow');   // 注意少了个 s
el.textContent = 'x';   // TypeError: Cannot read properties of null
```

排查顺序固定三步：

1. HTML 里那个 id 到底拼对没有（大小写敏感，`studentRows` ≠ `studentrows`）
2. `<script>` 是不是在元素**之前**执行了（见 1.3）
3. 元素是不是动态生成的，此刻还不存在

### 2.4 一个元素节点上最常看的属性

| 属性 | 含义 |
|------|------|
| `element.id` / `element.className` | id / class 字符串 |
| `element.classList` | 类名集合，见 3.4 |
| `element.dataset` | 所有 `data-*` 属性，见 3.4 |
| `element.children` | 子元素（不含文本） |
| `element.parentElement` | 父元素 |
| `element.tagName` | 大写的标签名，如 `"BUTTON"` |

## 3. 抓住之后怎么操作 ★★★

四类操作，覆盖你现在所有需求：**读值、写值、改状态、增删节点。**

### 3.1 读值 / 写值

| 你想改 | 用哪个 | 你项目里的例子 |
|--------|--------|----------------|
| 标签里的文字 | `textContent` | `statusText.textContent = '共 ' + list.length + ' 条'` |
| 表单控件的当前值 | `value` | `addForm.elements['name'].value` |
| 下拉框选中项 | `select.value` | `const classid = classSelect.value` |
| 复选框 | `checked` | — |
| 内部 HTML | `innerHTML` | `tbody.innerHTML = ''` 清空 |

**要点：`textContent` 读写的是纯文本，`innerHTML` 读写的是 HTML 源码。**

```js
el.textContent = '<b>hi</b>';   // 屏幕上原样显示 <b>hi</b>
el.innerHTML  = '<b>hi</b>';    // 屏幕上显示加粗的 hi
```

`innerHTML` 方便但危险：如果拼进去的内容来自用户输入，用户写个 `<img src=x onerror=alert(1)>` 就能执行脚本（XSS）。你现在数据是学生姓名，风险小，但**养成习惯：能用 textContent 就别用 innerHTML**，只有确实要生成结构时才用。

### 3.2 创建并插入节点（renderRows 的套路）

```js
const tr = document.createElement('tr');   // 1. 造一个空壳
tr.innerHTML = `<td>${s.id}</td>...`;      // 2. 往里塞内容/子结构
tbody.appendChild(tr);                     // 3. 挂到树上，屏幕才出现
```

三步缺一不可：**createElement 造出来的节点在内存里，没 append 到 document 上，用户永远看不见。**

其他插入方法：

```js
parent.appendChild(node)      // 加到末尾
parent.prepend(node)          // 加到最前
parent.insertBefore(node, ref)// 插到 ref 前面
node.remove()                 // 自己把自己删掉
parent.innerHTML = ''         // 最快清空所有子节点
```

⚠️ `appendChild` 一个已经在页面上的节点，等于**移动**它，不是复制。要复制用 `node.cloneNode(true)`。

### 3.3 表格重建的完整循环

`renderRows` 干的事，用文字描述就是：

```
1. 缓存数据 list → currentList    （为了后面 startEdit 能查到这一行）
2. tbody.innerHTML = ''           （清掉旧数据）
3. 空数组？→ 显示提示文字，return
4. 有数据 → 隐藏提示，for 循环：每行造 tr、塞 7 个 td、append
```

**这个"清空 → 重建"模式是最笨也最不容易出错的渲染方式**，几十条数据完全够用。等以后数据上千条才需要"只改变化的那一行"这类优化。

### 3.4 classList / dataset / hidden 三个神器

**classList** —— 改 class 而不动 style，样式规则交给 CSS：

```js
el.classList.add('active');
el.classList.remove('active');
el.classList.toggle('active');       // 有就删，没有就加
el.classList.contains('delete');     // 返回 true/false，事件委托靠它判断
```

**dataset** —— 读 HTML 上的 `data-*` 自定义属性，用来把"这条记录的 id"贴在按钮上：

```html
<button class="delete" data-id="7">删除</button>
```
```js
btn.dataset.id        // "7"  ← 注意是字符串！
btn.dataset.studentId // 对应 data-student-id，驼峰转连字符
```

命名规则：`data-abc-def` → `dataset.abcDef`。这就是 `app.js` 里 `data-id="${s.id}"` 和 `target.dataset.id` 的配对关系。

**hidden** —— 布尔属性，等价于 `display:none`：

```js
emptyTip.hidden = false;   // 显示
emptyTip.hidden = true;    // 隐藏
```

比 `style.display = 'none'` 好处是语义清楚，而且 CSS 里还能覆盖。

### 3.5 一个必踩的坑：id 类型不一致

后端 `id` 是 `int`，经过 JSON 到了 JS 还是数字 `7`。但 `dataset.id` 永远是**字符串** `"7"`。

```js
7 === "7"            // false  ← 用 === 永远对不上
String(item.id) === String(id)   // true  ← 你代码里的写法，就是在防这个
```

同理 `classSelect.value` 永远是字符串，`Number(classSelect.value)` 才拿到数字。

## 4. 事件：谁在听，听什么，听完做什么 ★★★

### 4.1 addEventListener 三要素

```js
元素.addEventListener('事件名', 处理函数);
```

```js
classSelect.addEventListener('change', loadStudents);      // 直接给函数名
reloadBtn.addEventListener('click', () => { ... });        // 需要传参/多行就写箭头函数
addForm.addEventListener('submit', submitForm);
```

| 事件名 | 什么时候触发 | 用在 |
|--------|--------------|------|
| `click` | 点一下 | 按钮、行内操作 |
| `change` | 值改了并且失焦（下拉选完） | select、input |
| `input` | 每敲一个字符 | 实时搜索 |
| `submit` | 表单提交（点 submit 按钮或回车） | form |
| `DOMContentLoaded` | HTML 解析完 | 想放 head 的脚本 |

⚠️ `loadStudents` 后面**不能加括号**。`loadStudents` 是"把函数本身交出去"，`loadStudents()` 是"立刻执行，把返回值交出去"，后者会让加载在你绑定的瞬间就跑一次，之后点击反而没反应。

### 4.2 事件对象 e

浏览器调用你的处理函数时，会自动塞进来一个参数：

```js
addForm.addEventListener('submit', function (e) {
  e.preventDefault();          // 阻止默认行为
});
```

| 成员 | 含义 |
|------|------|
| `e.target` | **真正被点中的那个元素** |
| `e.currentTarget` | **绑定监听器的那个元素**（等于函数里的 `this`） |
| `e.preventDefault()` | 取消默认行为（表单提交跳页、链接跳转） |
| `e.stopPropagation()` | 阻止事件继续往上冒泡 |

### 4.3 为什么表单必须 preventDefault ★★★

`<form>` 的默认行为是：把表单字段拼成 query 发给当前地址，**整页刷新**。

你现在是纯前端 + fetch，一旦刷新，JS 状态全丢（`editingId` 变 null），页面回到初始状态。所以 `submitForm` 第一行就是 `e.preventDefault()`。

**这是最容易忘的一行**，症状很有辨识度：点提交，页面闪一下，什么都没发生，控制台日志也清了。

### 4.4 事件委托（重点）★★★

你的表格行是 `renderRows` 动态生成的。如果给每个按钮单独绑：

```js
// 不推荐
document.querySelectorAll('.delete').forEach(btn => {
  btn.addEventListener('click', ...);
});
```

问题：**每次重新渲染（删一条、加一条）都得重新绑一遍**，否则新行上的按钮是死的。

委托的做法：把监听器绑在**一直存在的父节点** `tbody` 上，靠冒泡接住子元素的点击。

```
点击「删除」按钮
   ↓ 事件冒泡（从下往上）
button.delete → td → tr → tbody  ← 监听器在这
   ↓
处理函数收到 e，e.target 仍然是那个 button
```

```js
tbody.addEventListener('click', async (e) => {
  const target = e.target;
  if (target.classList.contains('update')) { ... }
  if (!target.classList.contains('delete')) return;
  await removeStudent(target.dataset.id);
});
```

三个要点：

1. **只绑一次**，写在顶层，不管表格重渲染多少次都有效
2. `e.target` 判断"点的是什么"，`classList.contains` 是标准判断方式
3. `dataset.id` 从被点的按钮上取到"操作哪一行"

更稳的写法是 `e.target.closest('button')`——万一按钮里还套了 `<span>`，`e.target` 会变成 span，`contains('delete')` 就判断失败了：

```js
const btn = e.target.closest('button');
if (!btn) return;
if (btn.classList.contains('delete')) { ... }
```

### 4.5 confirm 是同步阻塞的

```js
if (!confirm('确定删除？')) return;
```

`confirm` 会**卡住整个页面**等用户点确定/取消，返回 `true/false`。所以它能直接写在 `if` 里。
（`alert`、`prompt` 同理。真正的对话框要用 `<dialog>` 或自定义 DOM，那是后话。）

## 5. 表单：从用户输入到 JS 对象 ★★

### 5.1 name 属性才是数据的钥匙

```html
<input name="name" type="text" required>
<select name="gender">...</select>
<input name="age" type="number">
```

`id` 是给 JS 找元素用的，`name` 是给表单收集数据用的。**两个是不同的东西**，只是习惯上写成一样。

### 5.2 FormData：一次拿全表单

```js
const fd = new FormData(addForm);
fd.get('name')     // "张三"
fd.get('gender')   // "男"
fd.get('age')      // "20"  ← 字符串！
```

`readForm()` 就是把它转成一个干净的 JS 对象，顺手把类型转对：

```js
function readForm() {
  const fd = new FormData(addForm);
  return {
    name: fd.get('name'),
    gender: fd.get('gender'),
    age: Number(fd.get('age')),
    classid: Number(classSelect.value),
    phone: fd.get('phone')
  };
}
```

这个对象的形状，**就是后端 `Student` 类的形状**——字段名必须一模一样（`classid` 不能写成 `classId`），否则 Jackson 拿不到值，字段就是 0 / null。

### 5.3 数字转换的坑 ★★

| 表达式 | 结果 | 说明 |
|--------|------|------|
| `Number('20')` | `20` | 正常 |
| `Number('')` | `0` | **空字符串变 0，不是 NaN** |
| `Number('abc')` | `NaN` | 转不了 |
| `Number(null)` | `0` | 又一个坑 |
| `Number(undefined)` | `NaN` | |
| `Number.isFinite(NaN)` | `false` | 判断"是不是有效数字"最稳 |

所以校验不能只写 `!payload.age`（0 也被当成假），要用：

```js
!Number.isFinite(payload.age)   // 你代码里的写法，NaN / Infinity 都能拦住
```

真正兜底的是浏览器：`<input type="number" min="1" max="150" required>`，`required` 和 `min/max` 会在 submit 前由浏览器自动校验，不通过根本不会触发 submit 事件。

### 5.4 新增和编辑共用一个表单 ★★

`editingId` 这个全局变量的作用：**同一个表单，靠它区分"现在是新增还是改"**。

```js
let editingId = null;   // null = 新增模式；有数字 = 正在编辑这个 id

function startEdit(id) { editingId = s.id; ... }        // 点「编辑」进入编辑模式
function finishEdit()  { editingId = null; addForm.reset(); ... }  // 收尾回新增模式

if (editingId === null) await createStudent(payload);   // 分流
else                    await updateStudent(editingId, payload);
```

`startEdit` 里还有一句 `currentList.find(...)`：它是从**内存里已有的数据**找，不是再请求一次后端。这就是为什么 `renderRows` 要把 `currentList = list` 存下来。

## 6. 异步：async / await / Promise ★★★

### 6.1 为什么会有这套东西

JS 是**单线程**的。如果 `fetch` 是同步的，那么等后端响应（可能几百毫秒到几秒）期间，整个页面会冻住——滚动不了、按钮点不动。

所以浏览器把"等网络"这类耗时操作交出去，**先让 JS 把后面的代码执行完**，等结果到了再回来接着跑。这就是异步。

```js
console.log('1');
fetch('/api/classes').then(() => console.log('3'));
console.log('2');
// 输出顺序：1 2 3   ← 不是 1 3 2
```

### 6.2 Promise 是一张"欠条"

`fetch()` 立刻返回一个 Promise 对象，不是数据。它的意思是"数据还没有，但我保证以后给你"。

Promise 有三种状态：`pending`（等待）→ `fulfilled`（成功）/ `rejected`（失败）。**状态只能变一次，变了就锁死。**

```js
const p = fetch('/api/classes');
console.log(p);   // Promise {<pending>}
```

对着 pending 调 `.length`、`.json` 都会拿到 `undefined` —— **这是新手第二大报错来源：忘了 await。**

```js
const res = fetch('/api/classes');
console.log(res.ok);          // undefined  ← res 是 Promise，不是 Response
```

### 6.3 async/await 只是 Promise 的语法糖

```js
// then 写法
function loadClasses() {
  return fetch('/api/classes')
    .then(res => res.json())
    .then(list => { ... });
}

// async/await 写法（你现在用的）
async function loadClasses() {
  const res  = await fetch('/api/classes');
  const list = await res.json();
  ...
}
```

规则只有三条：

1. `await` 只能写在 `async` 函数里面
2. `await` 后面接 Promise，它会**暂停当前函数**，等结果出来再往下走（暂停的只是这个函数，页面照常响应）
3. `async` 函数**永远返回 Promise**，调用它的人要么 `await`，要么 `.then()`

你项目里 `submitForm` 调 `await createStudent(payload)`，就是因为它俩都是 async。

### 6.4 为什么 fetch 要 await 两次 ★★★

```js
const res  = await fetch(url);    // 第一次：等到"响应头"到达，拿到 Response
const data = await res.json();    // 第二次：等到"响应体"下载完并解析成 JS 对象
```

| 对象 | 你能读到什么 |
|------|--------------|
| `Response`（`res`） | `res.status`、`res.ok`、`res.headers`、`res.json()`、`res.text()` |
| 解析后的数据 | 真正的业务数据，比如 `[{id:8, classname:'计科1班'}]` |

`res.json()` 也要 await，因为响应体是**流**，可能没下载完。而且它内部还会执行 `JSON.parse`。

**一个 Response 的 body 只能读一次。** 读了 `res.json()` 就不能再 `res.text()`，会报 `body stream already read`。

### 6.5 fetch 不会因为 404/500 而 reject ★★★

这是最反直觉的一点：

```js
try {
  const res = await fetch('/api/students');   // 后端返回 500
} catch (e) {
  // 这里不会进来！
}
```

`fetch` 只在**网络层失败**（断网、域名解析不了、请求被 CORS 拦）时 reject。
只要服务器回了响应，哪怕是 500，Promise 也是 fulfilled。

所以状态码必须**手动判断**：

```js
if (!res.ok) { ... }          // res.ok === (status >= 200 && status < 300)
if (res.status === 409) { ... }  // 需要精细区分时看具体码
if (res.status !== 201) { ... }
```

你项目里每个请求函数都写了 `if (res.status !== 201)` 这类判断，就是为了补上 fetch 不管的这块。

### 6.6 try/catch 该包哪一段

```js
async function createStudent(payload) {
  try {
    const res = await fetch(url, {...});
    if (res.status === 409) { ...; return; }
    if (res.status !== 201) { ...; return; }
    await loadStudents();
  } catch (err) {
    statusText.textContent = '网络请求失败';
  }
}
```

- `try` 里只放**可能失败的异步调用**（fetch、res.json）
- 业务状态码（409/404）用 `if` 处理，**不要用 catch**，它们不是异常
- `catch` 兜的是断网、服务器挂掉、JSON 格式错误这类

### 6.7 需要并发时用 Promise.all

```js
const [classes, students] = await Promise.all([
  fetch('/api/classes').then(r => r.json()),
  fetch('/api/students?classid=8').then(r => r.json())
]);
```

两个请求同时发，总耗时 = 最慢的那个，而不是两个相加。你项目里是先后依赖（先有班级才能选班查学生），所以暂时用不上。

## 7. HTTP：前后端唯一的通道 ★★★

### 7.1 一次请求由四样东西组成

```
POST /api/students/7?force=true HTTP/1.1     ← ① 方法 + ② 路径(含 query)
Content-Type: application/json                ← ③ 请求头
                                              ← (空行)
{"name":"张三","age":20}                       ← ④ 请求体
```

| 部分 | 前端怎么给 | 后端怎么取 |
|------|-----------|-----------|
| 方法 | `fetch(url, { method: 'POST' })` | `exchange.getRequestMethod()` |
| 路径 | `fetch('/api/students/7')` | `getRequestURI().getPath()` → `pathId()` |
| query | `fetch('/api/students?classid=8')` | `getRequestURI().getRawQuery()` → `queryParam()` |
| 头 | `headers: { 'Content-Type': 'application/json' }` | `getRequestHeaders().getFirst(...)` |
| 体 | `body: JSON.stringify(payload)` | `exchange.getRequestBody()` → `readBody()` |

### 7.2 五个方法，语义要分清

| 方法 | 干什么 | 幂等 | 有没有 body | 你项目里的用法 |
|------|--------|------|-------------|----------------|
| GET | 查 | 是 | 无 | 查班级列表、查某班学生 |
| POST | 增 | 否 | 有 | 新增学生 |
| PUT | 全量改 | 是 | 有 | 修改学生（带完整对象） |
| PATCH | 部分改 | 否 | 有 | 未实现 |
| DELETE | 删 | 是 | 通常无 | 删除学生 |

**幂等** = 同样的请求发 10 次，结果和第 1 次一样。GET/PUT/DELETE 幂等，POST 不幂等（发 10 次就有 10 条记录）。这不是学术概念，是前端做重试、缓存时的依据。

### 7.3 状态码，前端要认得的就这些

| 码 | 含义 | 你项目里什么时候出现 |
|----|------|----------------------|
| 200 | 成功 | GET 查询、PUT 修改成功 |
| 201 | 创建成功 | POST 新增成功 |
| 204 | 成功但无内容 | DELETE 成功（所以**不能 res.json()**） |
| 400 | 请求有问题 | 缺 classid、id 不是数字 |
| 404 | 资源不存在 | 改/删不存在的学生 |
| 405 | 方法不支持 | 用了 PATCH |
| 409 | 冲突 | 姓名重复 |
| 500 | 服务器内部错误 | Handler 里抛异常被 catch |

**2xx = 成功，4xx = 你（前端）的错，5xx = 我的（后端）的错。** 记住这个分类就够排查用了。

### 7.4 204 的特殊处理

```java
// 后端
exchange.sendResponseHeaders(204, -1);
exchange.getResponseBody().close();
```
```js
// 前端：只判断状态码，不要读 body
if (res.status !== 204) { ... }
```

对 204 调 `res.json()` 会抛 `SyntaxError: Unexpected end of JSON input`。

### 7.5 query 参数 vs 路径参数，怎么选

| 场景 | 用法 | 例子 |
|------|------|------|
| 定位**一个**资源 | 路径 | `/api/students/7` → 学号 7 这个人 |
| **筛/shaping** 一个集合 | query | `/api/students?classid=8` → 8 班的所有人 |
| 可有可无的修饰 | query | `?page=2&size=20` |

判断口诀：**去掉它这个 URL 还指向同一类资源 → 用 query；指向完全不同了 → 用路径。**

### 7.6 为什么必须设 Content-Type

```js
headers: { 'Content-Type': 'application/json' }
```

这是告诉后端："我 body 里是 JSON 文本，请按 JSON 解析"。

你现在后端没检查这个头，直接 `readValue(body, Student.class)` 硬解析，所以不设也能跑。但一旦换成 Spring Boot，或者以后要支持表单提交，**缺这个头就是 415 Unsupported Media Type**。习惯现在就养成。

`GET` 没有 body，所以不需要设；`DELETE` 通常也不需要。

## 8. JSON：两端的翻译官 ★★★

### 8.1 为什么不能直接把对象传过去

HTTP 报文本质是**字节流**，只能承载文本/二进制。JS 对象、Java 对象都在各自的内存里，跨不过进程边界。所以必须序列化（对象 → 文本）再反序列化（文本 → 对象）。

JSON 就是两边都认的那套文本格式：

```json
{
  "id": 7,
  "name": "张三",
  "gender": "男",
  "age": 20,
  "classid": 8,
  "phone": "13800000000"
}
```

规则很死：key 必须双引号、不能有注释、不能有尾逗号、值只能是 string/number/boolean/null/array/object。

### 8.2 四个转换点，前后端各两个

| 方向 | 代码 | 结果 |
|------|------|------|
| JS 对象 → JSON 文本 | `JSON.stringify(payload)` | `'{"name":"张三","age":20}'` |
| JSON 文本 → JS 对象 | `await res.json()`（内部 `JSON.parse`） | `[{id:8,...}]` |
| JSON 文本 → Java 对象 | `Json.MAPPER.readValue(body, Student.class)` | `Student` 实例 |
| Java 对象 → JSON 文本 | `Json.MAPPER.writeValueAsString(value)` | `'{"id":7,...}'` |

**口诀：stringify 是"打包"，parse / readValue / json 是"拆包"。**

### 8.3 字段名必须完全对齐 ★★★

| JS 里写的 | Java 里叫 | 对不对 |
|-----------|-----------|--------|
| `classid` | `private int classid;` | ✅ |
| `classId` | `classid` | ❌ Jackson 找不到，值丢 |
| `phone: null` | `String phone` | ✅ 变 null |
| `age: null` | `int age` | ❌ 基本类型不能为 null，抛异常 |

Jackson 的默认匹配规则：**getter/setter 推出的属性名，精确匹配 JSON 的 key**（大小写敏感）。

`Student` 有 `getId()` → 属性名 `id`；`getClassid()` → 属性名 `classid`（不是 `classId`）。这个类没有 `@JsonProperty` 注解，所以就是**裸名对齐**。

### 8.4 Jackson 的两个默认行为要记住

1. **需要无参构造 + setter**。`Student` 有 `public Student() {}` 和全套 setter，所以能反序列化。（只有全参构造没有无参构造的类，Jackson 会报 `InvalidDefinitionException`）
2. **遇到未知字段默认抛异常**。前端多传一个 `{"name":"张三","foo":1}`，会 `UnrecognizedPropertyException` → 你的 Handler catch 到 → 500。想去掉这个严格模式就配 `MAPPER.configure(DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES, false)`。

### 8.5 空值处理：`??` 和 `||`

```js
`<td>${s.phone ?? ''}</td>`
```

`??` 是**空值合并**：只有左边是 `null` 或 `undefined` 时才用右边。

| 写法 | `null` | `undefined` | `''` | `0` |
|------|--------|-------------|------|-----|
| `a ?? 'x'` | `'x'` | `'x'` | `''` | `0` |
| `a \|\| 'x'` | `'x'` | `'x'` | `'x'` | `'x'` ← 0 被吃掉了 |

所以取可能是 0 的数值时，一定要用 `??` 而不是 `||`。

## 9. 你项目的接口清单（背下来）★★★

| 方法 | 路径 | 请求体 | 成功码 | 失败码 | 前端函数 |
|------|------|--------|--------|--------|----------|
| GET | `/` | — | 200 html | 404 | 浏览器自动 |

## 10. 常见坑清单（按踩坑概率排序）

| # | 现象 | 原因 | 解法 |
|---|------|------|------|
| 1 | `Cannot read properties of null` | 脚本在元素之前执行 / id 拼错 | 脚本放 body 末尾，或 `defer` |
| 2 | `res.ok` 是 `undefined` | 忘了 `await`，拿到的是 Promise | `const res = await fetch(...)` |
| 3 | 点了提交页面闪一下没反应 | 忘了 `e.preventDefault()` | 处理函数第一行加 |
| 4 | 新增的行上按钮没反应 | 按钮是动态生成的，没绑事件 | 事件委托到 tbody |
| 5 | `SyntaxError: Unexpected end of JSON input` | 对 204 调了 `res.json()` | 204 只判断状态码 |
| 6 | 后端收到全是 0 / null | 字段名不匹配（`classId` vs `classid`） | 严格对齐 Student 字段名 |
| 7 | `7 === "7"` 为 false | dataset 值是字符串 | `String(a) === String(b)` |
| 8 | 改了 js 刷新没变化 | 浏览器缓存 | Ctrl + F5 |
| 9 | 选完班级学生列表不刷新 | 监听的是 `click` 而不是 `change` | select 用 `change` |
| 10 | 500 且日志里有 `UnrecognizedPropertyException` | 多传了 Student 没有的字段 | 别多传，或关掉严格模式 |
| 11 | 端口占用 `Address already in use` | 上次的 Java 进程没退 | 杀掉进程 / 换端口 |
| 12 | 页面上显示 `<b>xx</b>` 原文 | 用了 textContent | 需要结构才用 innerHTML |
| 13 | 删除后序号全乱/残留 | 没清空就 append | 先 `tbody.innerHTML = ''` |

第 1、2、4 条吃掉新手 80% 的时间，遇到报错先往这三条上想。

## 附：一张对照表（JS 写法 ↔ Java 写法）

因为你是后端转过来，这个对照能省很多时间。

| 想干的事 | JS | Java（你的项目） |
|----------|-----|------------------|
| 定义类/对象 | `{name:'张三', age:20}` | `new Student("张三","男",20,8,"")` |
| 数组遍历 | `for (const s of list)` | `for (Student s : list)` |
| 过滤 | `list.filter(s => s.age > 18)` | `list.stream().filter(s -> s.getAge() > 18).toList()` |
| 查找 | `list.find(s => s.id === id)` | `stream().filter(...).findFirst()` |
| 字符串拼接 | `` `共 ${n} 条` `` | `"共 " + n + " 条"` |
| 空值保护 | `s.phone ?? ''` | `Objects.requireNonNullElse(s.getPhone(), "")` |
| 解析整数 | `Number(x)` / `parseInt(x, 10)` | `Integer.parseInt(x)` |
| 序列化 | `JSON.stringify(obj)` | `MAPPER.writeValueAsString(obj)` |
| 判断相等 | `===`（类型也相等才算） | `==` 引用比 / `equals` 内容比 |
| 函数定义 | `function f(a) {}` / `const f = a => {}` | `void f(int a) {}` |
| 变量声明 | `const` / `let`（没有块级 `var`） | `final` / 普通局部变量 |

最大的思维差异：**JS 是动态类型 + 函数是一等公民（能当参数传、能返回）**。`addEventListener('click', loadStudents)` 之所以能把函数当值传，就是第二条。Java 里对应的是 `Runnable` / lambda。
